# Node ID Generation Fix

## Problem

The system was wastefully asking the LLM to generate node IDs, then immediately discarding them and regenerating programmatically:

```
LLM generates: day1_node1, day1_node2, day1_node3...
Code detects: "Duplicate node ID: day1_node1" (conflicts with pre-created infrastructure nodes)
Code regenerates: day1_node7, day1_node8, day1_node9...
```

This caused:
- Wasted LLM tokens generating IDs that are thrown away
- Error logs for every single node
- Unnecessary validation overhead
- Confusion in logs

## Root Cause

1. **Schema included `"id"` field** - Even though not required, LLMs tend to fill all properties
2. **Prompt instructed LLM to generate IDs** - "Use node IDs in format 'day{N}_node{M}'"
3. **Code always regenerates IDs anyway** - Has validation and regeneration logic

## Solution

**Remove ID generation from LLM responsibility entirely:**

### 1. SkeletonPlannerAgent.java
- ✅ Removed `"id"` from JSON schema properties
- ✅ Removed prompt instruction: "CRITICAL: Use node ID format..."
- ✅ Added instruction: "DO NOT generate node IDs - they will be assigned automatically"
- ✅ Changed user prompt: "Do NOT include 'id' field in nodes"

### 2. DayByDayPlannerAgent.java
- ✅ Removed `"id"` from JSON schema properties
- ✅ Removed `"id"` from required fields array

### 3. Existing Code (No Changes Needed)
- ✅ `generateDaySkeleton()` already assigns IDs programmatically
- ✅ `NodeIdGenerator` handles ID generation
- ✅ Validation ensures uniqueness

## Benefits

1. **Reduced LLM Token Usage** - No longer generating IDs that are discarded
2. **Cleaner Logs** - No more "Invalid node ID" / "Duplicate node ID" errors
3. **Faster Processing** - Less validation overhead
4. **Simpler Logic** - Single source of truth for ID generation
5. **More Reliable** - Programmatic IDs are always correct format

## How It Works Now

```
LLM Response:
{
  "nodes": [
    {
      "type": "meal",
      "title": "Morning Breakfast",
      "timing": {...}
    }
  ]
}

Code Processing:
1. Parse LLM response (no ID field)
2. Assign ID: day1_node1 (using NodeIdGenerator)
3. Validate uniqueness
4. Save to database

Result: Clean, efficient, no errors
```
